How we use AssemblyAI

Voice Agent API

  • Recognition, turn detection, barge-in, tool calling and speech over one WebSocket, relayed by our server so the key never reaches the browser
  • Every tool.call is a proposal: held until reply.done, dropped if the user interrupts
  • Tools follow state: commit exists only while a valid preview does
  • Keyterms narrow to the options being asked about
  • reply.create lets the agent announce reality changes unprompted

LLM Gateway

  • Reads typed phrasing the rule-based parser can’t
  • Its JSON goes through the same tools and the same evidence gate
  • Live: “yep sounds right to me” came back as commit. The backend refused.
AssemblyAI does the conversation: recognition, turn-taking, barge-in, tool calls and the voice. MIRROR decides what the tool calls are allowed to do. Calls wait for the reply to finish and vanish if you interrupt, so an interrupted commit cannot run. The tool list changes with the transaction state. The LLM Gateway handles free-form typing, and the live test shows why the gate matters: the model read agreement as a commit, and the backend refused it.
